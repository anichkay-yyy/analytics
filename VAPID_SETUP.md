## Нужно получить приватный ключ

### ❗ Вопрос: Один приватный VAPID ключ на приложение?

**Да!** Пара VAPID ключей (публичный + приватный) создается **один раз для всего приложения** и используется для всех пользователей:

- **Публичный ключ** - отправляется всем клиентам (браузерам) для подписки
- **Приватный ключ** - хранится **только на сервере**, используется для отправки уведомлений

### Как получить приватный ключ:

#### Вариант 1: У вас уже есть пара ключей

Если вы генерировали ключи ранее и получили публичный ключ `BEOn_h5tsl1SdhAttG84ajsYboWRIumDib4luzYE34dsTy5ntHinjVF5kMg5CjxavzdQc6Pbp-m866txIBajms4`, то у вас должен быть и приватный ключ.

Найдите его и добавьте в `/home/anichkay/analytics/server/.env`:

```env
VAPID_PRIVATE_KEY="ваш-приватный-ключ-здесь"
```

#### Вариант 2: Сгенерировать новую пару

Если приватный ключ потерян, нужно создать новую пару:

```bash
cd /home/anichkay/analytics/server
npx web-push generate-vapid-keys
```

Вы получите:
```
=======================================
Public Key:
BNew_public_key_here...

Private Key:
new_private_key_here...
=======================================
```

**ВАЖНО:** Если создаете новую пару, нужно будет обновить публичный ключ везде:
1. В `server/.env`
2. В `server/.env.example`

## Текущая ситуация

✅ **Создан** `server/.env` с вашим публичным ключом
❌ **Нужно добавить** приватный ключ

### Откройте файл:

```bash
nano /home/anichkay/analytics/server/.env
```

Или в любом редакторе, и замените:

```env
VAPID_PRIVATE_KEY="REPLACE_WITH_YOUR_PRIVATE_KEY"
```

На ваш настоящий приватный ключ.

## Проверка

После добавления приватного ключа:

```bash
cd /home/anichkay/analytics/server
npm run dev
```

Вы должны увидеть:
```
✓ Web Push configured with VAPID keys
```

Если видите:
```
⚠ VAPID keys not configured
```

Значит ключ добавлен неправильно или файл .env не загружается.

## Безопасность

⚠️ **НЕ КОММИТЬТЕ** `.env` файл в git!
- `.env` уже добавлен в `.gitignore`
- Приватный ключ должен быть **только на сервере**
- Каждое окружение (dev/prod) использует свой `.env`
